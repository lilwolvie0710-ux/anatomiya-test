# Anatomiya test — офлайн-тесты по анатомии человека

Веб-приложение (PWA) для тестирования студентов 1 курса по дисциплине **HUMAN ANATOMY 1** (AN 112312).
Работает на iPhone (Safari) и Android (Chrome), ставится на главный экран и после первой загрузки работает **без интернета**.
Сервера и регистрации нет: всё хранится на устройстве (IndexedDB).

- Интерфейс: узбекский (латиница) и русский, переключение в «Настройках».
- Термины — на латыни по Terminologia Anatomica.
- Экзамен по умолчанию: 30 заданий, 40 минут, балл от 0 до 2.0 с шагом 0.1 (доля верных × 2, округление вниз до десятых). Всё настраивается в каждом тесте.

## 1. Как опубликовать (GitHub Pages)

Нужно один раз:

1. Создайте аккаунт на <https://github.com> и **публичный** репозиторий, например `anatomiya-test`.
   (Бесплатный GitHub Pages работает только с публичными репозиториями. Код и банк тренировочных вопросов будут видны всем — см. раздел 6.)
2. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. На компьютере в папке проекта:

```powershell
git init -b main
git add .
git commit -m "Первая версия"
git remote add origin https://github.com/<ваш-логин>/anatomiya-test.git
git push -u origin main
```

4. Через 1–2 минуты (вкладка **Actions**) приложение будет доступно по адресу
   `https://<ваш-логин>.github.io/anatomiya-test/`.

Каждый следующий `git push` автоматически проверяет банк вопросов, запускает тесты и публикует новую версию.
Телефоны студентов получат обновление при следующем открытии приложения **с интернетом**.

> Обновляйте приложение заранее, а не перед самым тестом: в авиарежиме телефон останется на старой версии.

### Локальная разработка

```powershell
npm install
npm run dev
```

Проверки: `npm test` (логика), `npm run test:e2e` (сквозной сценарий в эмуляции iPhone 13 и Pixel 7), `npm run validate` (банк вопросов).

## 2. Как студенту установить приложение

Ссылку на приложение отправьте студентам заранее (например, в Telegram-группу). Открывать её нужно **с интернетом** — один раз.

### iPhone (Safari)

1. Откройте ссылку **в Safari** (не во встроенном браузере Telegram: нажмите «⋯» → «Открыть в Safari»).
2. Кнопка «Поделиться» (квадрат со стрелкой) → **«На экран “Домой”»** → «Добавить».
3. Запустите приложение с главного экрана и заполните профиль: ФИО, группа, факультет.

### Android (Chrome)

1. Откройте ссылку в Chrome.
2. Меню «⋮» → **«Установить приложение»** (или «Добавить на главный экран»).
3. Запустите с главного экрана и заполните профиль.

После этого приложение работает в авиарежиме. Проверить: включите авиарежим и откройте приложение — должно открыться.

## 3. Как провести тест

### Вход преподавателя

1. Откройте приложение (сайт или значок на главном экране) → плитка **«O‘qituvchi / Преподаватель»** (значок 🔒).
2. **Первый вход на этом устройстве:** придумайте PIN (4–8 цифр), введите дважды → «Сохранить PIN».
3. Дальше вход — по этому PIN. Выход — кнопка 🔒 вверху; после перезагрузки приложения PIN спросят снова.
4. PIN свой на каждом устройстве. Сбросить его можно только очисткой данных сайта (журнал при этом удалится — заранее делайте «Резервную копию»).

### Готовый файл экзамена без приложения (с компьютера)

```powershell
npm run exam -- --topics 1-8 --count 30 --minutes 40
```

Создаёт `exams/imtihon-<ID>.json` (отправить студентам) и `exams/imtihon-<ID>-KOD.txt` с кодом старта. Папка `exams/` не публикуется.
Чтобы проверять QR-коды по этому тесту, импортируйте файл на телефон преподавателя: **Преподаватель → Мои тесты → Импортировать файл теста** → введите код.
Пока вопросы в статусе `draft`, скрипт берёт и черновики; с флагом `--approved-only` — только утверждённые.

### Офлайн-тренажёр одним файлом (для Telegram)

```powershell
npm run offline
```

Собирает `docs/Anatomiya_oflayn.html` — один файл со всеми вопросами и картинками: тренировка и пробный тест (30 вопросов, 40 мин, 0–2.0).
Его можно отправить в Telegram; на Android он открывается в Chrome без интернета. Ответы находятся внутри файла, поэтому это только тренажёр, не экзамен.

### Перед занятием (преподаватель)

1. Откройте приложение → **Преподаватель** (при первом входе придумайте PIN).
2. **Конструктор теста**: выберите темы, число вопросов на студента (по умолчанию 30), время (40 мин), правила нарушений и перевод в балл (по умолчанию 0–2.0 с шагом 0.1; есть пороговая шкала 0/1/2 и «баллы за вопрос»).
   - «Размер пула»: если пул больше числа вопросов, каждый студент получит свой случайный набор.
   - В тест попадают только вопросы со статусом `approved`. Галочка «Включить черновики» — только для пробы.
3. Нажмите **«Создать зашифрованный файл»**. Появится **код старта** (вида `K7MP-4QX9`) — запишите его.
4. **«Отправить файл»** → Telegram → группа студентов. Без кода файл прочитать нельзя.

Тест хранится на вашем телефоне в «Мои тесты» — по нему проверяются результаты.
Если вы создавали тест на одном устройстве, а сканировать будете другим, импортируйте файл теста на второе устройство («Мои тесты → Импортировать», нужен код).

### На занятии

1. Студенты сохраняют файл из Telegram в «Файлы» (iPhone) или «Загрузки» (Android).
2. В приложении: **Экзамен → Загрузить файл теста**.
3. Вы **называете код вслух**, студенты вводят его.
4. Студенты включают **авиарежим** и выключают Wi-Fi. Пока устройство онлайн, кнопка «Начать» не активна.
5. **iPhone**: на экране будет инструкция по Гид-доступу. Студент трижды нажимает боковую кнопку, **код Гид-доступа вводите вы**. Выход после теста — тоже трижды боковая кнопка и ваш код.
   (Один раз заранее: Настройки → Универсальный доступ → Гид-доступ → включить.)
6. **Android**: при старте включается полноэкранный режим.
7. Студент нажимает «Начать». Таймер считает от фиксированного времени окончания: перезагрузка не даёт лишнего времени, ответы сохраняются.

### Нарушения (настраивается в конструкторе)

| Событие | Что происходит |
|---|---|
| Уход из приложения, сворачивание, закрытие, перезагрузка | 1-й раз — предупреждение, 2-й — автосдача |
| Потеря фокуса дольше 2 с (шторка уведомлений и т.п.) | считается уходом |
| Выход из полноэкранного режима (Android) | считается уходом |
| Появился интернет | записывается нарушение (без автосдачи) |
| Перевели часы на телефоне | записывается нарушение |

События, случившиеся в течение 3 секунд одно за другим (например, сворачивание + выход из полноэкранного режима), считаются одним уходом.
Все нарушения со временем попадают в результат.

### После теста

1. У студента на экране: балл, процент, время, число нарушений и **QR-код**.
2. **Преподаватель → Сканировать QR** → наведите камеру на экран студента. Результат сразу попадает в журнал.
   - Балл **пересчитывается по вашему ключу**: подделать балл в QR бесполезно.
   - Подпись HMAC проверяется. Если QR изменён, запись помечается «ПОДПИСЬ НЕВЕРНА».
   - Если QR не сканируется, студент нажимает «Сохранить результат файлом» и присылает файл. Вы загружаете его: «Сканировать → Добавить без QR».
3. **Журнал**: фильтр по группе и дате, экспорт в **Excel** и **CSV**.
4. **Статистика**: средний балл, распределение баллов, анализ каждого вопроса (процент верных и самые частые ошибки).
5. **Резервная копия**: регулярно сохраняйте журнал в файл (в нём есть коды тестов — храните его в надёжном месте). Восстановление — тем же экраном.

## 4. Как добавить вопросы

### Вариант А — через Excel (рекомендуется)

1. Откройте шаблон `templates/savollar-shablon.xlsx`. Лист «Инструкция» описывает все столбцы, на листе «Savollar» есть примеры всех типов.
2. Заполните вопросы и сохраните файл.
3. Преобразуйте в JSON:

```powershell
npm run xlsx2json -- templates\savollar-shablon.xlsx
```

Скрипт проверит каждую строку и покажет ошибки.

4. Дальше один из двух путей:
   - **Открытые вопросы** (для тренировки и экзамена): положите JSON в `src/content/bank/topic-XX.json` и сделайте `git push`.
   - **Закрытые экзаменационные вопросы**: в приложении «Преподаватель → Мои вопросы → Импорт JSON». Они хранятся только на вашем устройстве и попадают к студентам только внутри зашифрованного файла теста. Сам JSON **не кладите** в репозиторий.

### Вариант Б — прямо в JSON

Файлы банка: `src/content/bank/topic-01.json` и т.д. Каждый вопрос создаётся со статусом `"status": "draft"`.
После проверки поменяйте его на `"approved"`: только такие вопросы попадают в экзамен.
Проверка банка: `npm run validate`.

Перед выпуском поставьте `TRAINING_INCLUDE_DRAFTS = false` в `src/content/bank.ts`, чтобы студенты тренировались только на проверенных вопросах.

### Задания по рисунку

1. **Преподаватель → Редактор зон**: выберите картинку из приложения или загрузите свою.
2. Инструменты:
   - **Круг** — ведите пальцем от центра;
   - **Многоугольник** — точки касанием, затем «Замкнуть»;
   - **Маска** — белый прямоугольник поверх напечатанной подписи;
   - **Точка подписи** — для задания «Перетащите подписи».
3. Скопируйте JSON в столбец `extra_json` Excel-шаблона. Готовый вопрос из банка можно открыть в редакторе и проверить его зоны.

Координаты задаются в процентах от размеров картинки, поэтому зоны работают на любом экране.

## 6. Безопасность: что защищено и что нет

- **Файл теста** зашифрован AES-GCM 256, ключ получается из кода старта через PBKDF2 (600 000 итераций). Код — 8 символов (~37 бит), подобрать его перебором за время до теста практически нельзя.
- **Результат** подписан HMAC-SHA256 ключом из файла теста. Кроме того, балл пересчитывается у преподавателя по ответам. Слабое место: технически подготовленный студент, у которого есть код, теоретически может извлечь ключ из файла и изменить, например, список нарушений. Без сервера полностью исключить это нельзя.
- **Публичный репозиторий**: всё в `src/content/bank/` видно всем вместе с ответами. Закрытые экзаменационные вопросы держите в «Мои вопросы» (см. раздел 4).
- **PIN преподавателя** защищает только телефон преподавателя: это локальная проверка, не учётная запись.
- **Ограничения браузера**: скриншоты запретить нельзя; на iPhone полноэкранного режима нет (поэтому нужен Гид-доступ); Wi-Fi без интернета браузер считает «онлайн».

## 7. Структура проекта

```
src/
  core/          логика без интерфейса: оценка, латынь, шифрование, QR, нарушения
  content/       темы, банк вопросов (bank/*.json), реестр картинок (images.json)
  components/    задания всех типов, рисунок с масками, QR
  screens/       экраны студента
  teacher/       режим преподавателя
public/img/      картинки (кэшируются для офлайна)
scripts/         Excel-шаблон, конвертер Excel → JSON, проверка банка
tests/unit/      Vitest: оценка, латынь, шифрование, подпись QR
tests/e2e/       Playwright: iPhone 13 и Pixel 7, офлайн
syllabus/        силлабус
```
